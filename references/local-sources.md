# 本地招聘与补充渠道

四个新增渠道都是 Agent 使用 Tabbit 的可视检索流程，已接入计划、城市路线、预检、配额、证据筛选、报告与待办。不是新增四个 Python 自动采集适配器。

## 选渠道与确认

新建计划默认原五平台加 `bendibao`，每个平台 5 个，总目标 30 个。用户指定平台时原样采用；已有计划的显式平台、预算和确认 ID 不自动变化。新渠道须出现在确认摘要中。

| ID | 适用场景 | 不要混入的结果 |
|---|---|---|
| `bendibao` | 目标地区的企业职位、事业单位及当地招聘公告 | 邻市推荐、培训招生、考情资讯、成绩公示 |
| `guopin` | 用户接受的国企/央企及平台内其他企业招聘 | 把所有企业一概认定为国企；把校招混进仅限社招的计划 |
| `public_jobs` | 中国公共招聘网归集的公共就业服务岗位、招聘活动 | 将招聘会介绍直接当成具体岗位 |
| `ncss` | 用户接受的应届、校招和毕业生就业岗位 | 把毕业年份限制默认为满足；替在职社招用户改变方向 |

可建议后面三个渠道；在本轮计划确认时一起决定。平台选择不等于改变岗位、地点、学历或用工要求。查看 [来源核验记录](source-verification.md) 了解当前已验证范围。

## 本地宝：按用户期望地区定位

1. `plan` 同时写出同名 `*.routes.json`；也可运行 `job_search.py routes --plan PLAN --out ROUTES`。`scan` 输出 `search-routes.json`，`next-actions.json` 的每个平台也有 `search_routes`。这些只是路线，不能当作搜索结果。
2. `data/bendibao_cities.json` 保存官方城市导航的 379 个地区首页链接与核验日期。精确匹配城市名，支持末尾“市”；苏州/宿州、泰州/台州各自独立。不用拼音或招聘平台城市码拼本地宝网址，也不假设所有城市都有 `/job/search/`。
3. 从本轮已有同平台标签开始；有目标城市标签时优先使用。只读预检不会跳转用户标签。随后核对页眉地区，从当前可见“招聘、职位、招聘资讯”入口进入。已有标签若是其他城市，按当前页面的城市切换控件选择目标城市，不能在错误城市直接收集。
4. 全国、未收录地区及“海南/吉林/朝阳/兴安”等歧义名称先走官方城市导航。不能默认深圳、扩大为省级或邻市。县区若有独立站可选；否则确认所属城市，保留原县区约束。区县要求无法自动判定时放 `extra_requirements`，明确人工核实。
5. 对每个已确认的 `keyword × city`，在“职位”搜索中填岗位词并选地区；如果该站只提供招聘资讯，从可见栏目筛选，必要时使用路线中的 `discovery_query` 在 Tabbit 的搜索引擎页面发现站内公告。站外搜索结果只是线索：必须打开本地宝原页及可见的原始公告，不能将摘要或搜索日期当作岗位证据。搜索结果页也计入该渠道页预算。
6. 分开提取“单职位”与“招聘公告”。单职位用 `source_kind=job`；公告用 `announcement`。一篇公告有多个岗位时按真实职位表拆分，一条岗位对应一条记录，优先用公告号＋岗位代码作为 `id`。不能用“某单位招 50 人”冒充一个岗位，不能以人数填满配额。
7. 城市站首页会推荐周边城市。`city` 填岗位实际工作城市，`district` 填具体区县；站点城市不能代替工作地点。轮岗、多地点不明确、通勤等仍需核实。
8. “我要招人”、`u.bendibao.com` 招聘端、`/job/recruit` 招聘表单不是求职搜索。公开职位和公告可不登录读取；不要求用户为了阅读公开内容先注册、上传简历或扫码关注公众号。实际出现登录墙、验证码或 App 限制才记录阻塞。

## 另外三个渠道的检索

- **国聘**：从 `https://www.iguopin.com/` 可见的职位/社会招聘/校园招聘入口进入，选择已确认城市及岗位词，读取职位详情。JavaScript 壳不等于空结果。单位性质看实际企业信息，不由域名推断；公告中的届别、专业等进入资格核验。
- **中国公共招聘网**：从 `http://job.mohrss.gov.cn/` 当前可见的岗位搜索、地区入口开始；按城市和岗位检索。沿平台已展示的当地人社部门、公共就业机构或用人单位链接回溯原始招聘信息。地方网站只作为本条岗位的原始证据，记录 `original_url`；不伪造成平台域名，不把未注册的地方站算作已覆盖的独立平台。入口超时或不可访问记 `browser_error/access_denied`，不是 `empty`。
- **国家大学生就业服务平台**：从 `https://www.ncss.cn/` 的职位/招聘专区进入，用已确认城市、岗位词及求职类型筛选。区分毕业生就业岗位、实习、宣讲会、招聘会和单位公告。资格未知时保留待核实，不擅自推断毕业年份。

原始链接优先来自招聘页的“来源/原文/招聘官网”，核对用人单位及公告标题、年份、岗位代码。企业官方招聘页、人社部门原公告和职位表是补证渠道；沿同一招聘事项补证不增加岗位范围。不能仅因 URL 看起来官方就视为已经核验。独立扩搜其他地方人才网或企业官网时，先确认新增范围，本版没有通用的任意域名采集器。

## 公告证据与失效控制

- `publish_time` 只记录该岗位/原公告有明确依据的发布时间；本地宝等转载页的发布时间单独放 `source_publish_time`。刷新时间仍放 `refresh_time`，不能用转载日期把旧岗位变成新岗位。
- `recruitment_status` 为 `open/closed/not_started/unknown`，非 unknown 必须附 `recruitment_evidence` 原文。新四渠道要求核实当前是否在招；无 HR 活跃信息不会在默认计划中阻塞，但不能绕过用户明确要求的 `require_active=true`。
- `deadline` 保留截止原文；`deadline_at` 仅填能确定年份的 ISO 日期或带时区时间。日期只有年月日时视为当地当天结束；原文有 16:00 等精确时刻必须保留。招满即止、仅有月日或时间有歧义时留空标准值，进入待核实，不猜年份。公告没有截止时间也进入待核实。已经截止或下架直接排除；未开始报名进入待核实。
- 公告须保留 `original_url/original_evidence/original_captured_at`；若平台本身就是发布方，可以指向同一页，但要实际读过原文。原文打不开、附件未读或仅有公众号引流文字时，不把公告计入符合数量。
- 对照用户已提供事实核实专业、学历、届别、年龄、户籍、资格证等公告硬条件：`eligibility_status=matched/unmatched/unknown`，有判断就附 `eligibility_evidence`。没有额外限制也需记录原文依据。用户事实缺失时保持 unknown，不推断敏感或私人属性。
- 原文与转载冲突时以较新的、可验证的官方更正为依据，记录冲突和更正链接；不清楚则待核实。原文访问也计入同平台详情尝试预算，失败同样计数。`detail_urls` 仍只记本平台详情；另用 `original_detail_urls` 记真正访问的原始链接。

每个渠道独立目标、独立预算；多个城市共用该渠道已确认预算。没有继续结果/预算时按现有 worklist 规则说明不足；不要因新增渠道就突破上限或反复查询。标准字段见 [数据格式](data-contract.md)。
